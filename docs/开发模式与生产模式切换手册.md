# 开发模式与生产模式切换手册

> 适用项目：文昌智融平台（wczx-AI-Hub，Next.js 14 + Prisma + SQLite）
> 依据：`package.json` scripts、`AGENTS.md` §2/§3、`next.config.mjs`、`.env`、`src/lib/https-entry.ts`（2026-11-27 核对）
> 命令以 macOS 终端为主，Windows 写法见第 6 节。所有命令都在项目根目录执行。

---

## 0. 一句话记住

**开发和生产共用同一个 `.next/` 目录，所以两者不能在同一目录同时跑。切换时永远是“先停旧的，再起新的”。**

> ⛔ 不要在 `npm run dev` 正在运行的目录里执行 `npm run build`。
> 构建会覆盖 `.next/`，开发服务器随即报 `Cannot find module './xxxx.js'`、静态资源 404，整站白屏、无法登录（2026-11-12 真实事故）。

---

## 1. 两种模式的区别

| 项目 | 开发模式（dev） | 生产模式（production） |
|---|---|---|
| 启动命令 | `npm run dev`（即 `next dev`） | `npx prisma generate && npm run build` 后 `npx next start -H 0.0.0.0 -p 3000` |
| 改代码后 | 保存即热更新，无需重启 | **必须重新构建并重启**才生效 |
| 页面速度 | 首次打开每个页面要现场编译，较慢 | 预先编译好，速度快 |
| 报错显示 | 浏览器弹出详细错误层，方便调试 | 只显示通用错误页，详情在终端日志 |
| 类型检查 | 不检查 | 构建时检查，有类型错误直接构建失败（`ignoreBuildErrors: false`） |
| 访问地址 | `http://localhost:3000` | `http://localhost:3000`，局域网 `http://本机IP:3000` |
| 适用场景 | 写代码、改功能、调试 | 正式上课、给学生/教师使用、性能测试、交付前验收 |

两种模式下，以下内容**完全相同**，切换不会影响：

- **数据库**：都读 `.env` 里的 `DATABASE_URL`，切换模式不会换库、不会丢数据。
- **登录密钥**：都读项目根目录的 `.auth-secret`，切换后已登录的账号仍然有效。
- **HTTPS 入口**：两种模式启动时都会在 `3443` 端口开局域网 HTTPS 入口（学生平板录音用），`.env` 设置 `HTTPS_PORT=0` 可关闭。

---

## 2. 端口一览

| 端口 | 用途 | 说明 |
|---|---|---|
| 3000 | 主服务（dev 与 production 都用） | 本项目固定用 3000 |
| 3443 | 局域网 HTTPS 入口 | 转发到本机 `PORT`（默认 3000）；`HTTPS_PORT=0` 关闭 |

> ⚠️ 如果确实要换主端口，请用环境变量 `PORT`，不要只写 `-p`：
> `PORT=3001 npx next start -H 0.0.0.0`
> 原因：HTTPS 入口按 `process.env.PORT` 决定转发目标，只写 `-p 3001` 时它仍转发到 3000，学生录音会打不开。

查看端口被谁占用：

```bash
lsof -i :3000
lsof -i :3443
```

## 3. 切换前先确认数据库（每次都看一眼）

```bash
grep DATABASE_URL .env
node scripts/db-locate.mjs     # 输出当前真实数据库文件的绝对路径
```

- 正式数据库是 `DATABASE_URL="file:./dev.db"`，实际文件为 `prisma/dev.db`。
- ⚠️ **当前本机 `.env` 指向的是测试库 `file:/tmp/wczx-test.db`**（文件注释写着“本地隔离测试环境”）。如果要用生产模式正式上课，请先把它改回 `file:./dev.db`，否则用的是 `/tmp` 下的测试数据，而且 `/tmp` 重启电脑后可能被清空。
- 不要写成 `file:./prisma/dev.db`，那会解析成 `prisma/prisma/dev.db`，出现两个库并存。
- 本次代码如果改过 `prisma/schema.prisma`，切到生产前要先备份再同步表结构：

```bash
cp prisma/dev.db prisma/dev.db.bak-$(date +%Y%m%d-%H%M)   # 路径以 db-locate 的输出为准
npx prisma db push
```

> ⛔ 不要用 `prisma migrate reset`、`db:reset`，也不要用 `bash start.sh` 来启动（某些情况下会初始化出空库）。

## 4. 开发模式 → 生产模式

### 步骤 1：停掉开发服务器

在运行 `npm run dev` 的终端窗口按 **Ctrl + C**。找不到那个窗口时：

```bash
bash stop.sh                 # 杀掉占用 3000 端口的进程
# 或
pkill -f "next dev"
```

确认已停干净（没有输出才算停了）：

```bash
lsof -i :3000
```

### 步骤 2：（建议）类型检查

```bash
npx tsc --noEmit             # 要求 0 错误；有错误构建也会失败
```

### 步骤 3：生成 Prisma 客户端并构建

```bash
npx prisma generate && npm run build
```

> ⚠️ `npm run build` 本身**不含** `prisma generate`，必须连在一起执行。漏掉会出现 Prisma 客户端与 schema 不一致的错误。
> 构建大约需要几分钟，看到 `✓ Compiled successfully` 和路由列表即为成功。

### 步骤 4：启动生产服务

前台运行（窗口关了服务就停）：

```bash
npx next start -H 0.0.0.0 -p 3000
```

后台运行（关掉终端也继续跑，日志写入文件）：

```bash
mkdir -p logs
nohup npx next start -H 0.0.0.0 -p 3000 > logs/next-prod.log 2>&1 &
tail -f logs/next-prod.log   # 看日志，Ctrl + C 只退出查看，不会停服务
```

> `npm start` 等价于 `next start -H 0.0.0.0`（默认端口 3000），也可以用。

### 步骤 5：验证

- 浏览器打开 `http://localhost:3000`，能正常登录。
- 局域网其他设备访问 `http://本机IP:3000`。
- 日志中出现 `[HTTPS 入口] 已启动` 表示学生录音入口可用。

### 生产模式下又改了代码怎么办

生产模式不会自动更新。改完代码后重复：停服务 → `npx prisma generate && npm run build` → 启动。

```bash
pkill -9 -f next-server
npx prisma generate && npm run build
nohup npx next start -H 0.0.0.0 -p 3000 > logs/next-prod.log 2>&1 &
```

## 5. 生产模式 → 开发模式

### 步骤 1：停掉生产服务

```bash
pkill -9 -f next-server      # AGENTS.md 规定的停法
# 或
bash stop.sh
lsof -i :3000                # 确认没有输出
```

### 步骤 2：清掉生产构建产物

```bash
rm -rf .next
```

> 为什么要删：`.next/` 里是生产构建的文件，直接 `npm run dev` 有时会混用新旧文件，出现页面 404、样式丢失或 `Cannot find module`。删掉后开发服务器会重新生成，不影响数据库和上传文件。

### 步骤 3：启动开发服务器

```bash
npm run dev
```

看到 `Ready` 后打开 `http://localhost:3000`。首次打开每个页面要编译几秒，属正常现象。

## 6. Windows 对照写法

| 操作 | macOS / Linux | Windows（PowerShell / CMD） |
|---|---|---|
| 停服务 | `bash stop.sh` / `pkill -9 -f next-server` | 双击 `stop.bat`，或 `netstat -ano \| findstr :3000` 查 PID 后 `taskkill /PID <PID> /F` |
| 看端口 | `lsof -i :3000` | `netstat -ano \| findstr :3000` |
| 删构建目录 | `rm -rf .next` | `rmdir /s /q .next`（CMD）或 `Remove-Item -Recurse -Force .next`（PowerShell） |
| 构建 | `npx prisma generate && npm run build` | 同左（PowerShell 5 不支持 `&&` 时分两行执行） |
| 启动生产 | `npx next start -H 0.0.0.0 -p 3000` | 同左 |
| 启动开发 | `npm run dev` | 同左 |

## 7. 不想中断开发，又要验证生产构建

在**另一个检出目录**里构建，不碰正在跑 dev 的目录。例如 Claude 的 worktree `~/Desktop/wczx-AI-Hub-claude`：

```bash
cd ~/Desktop/wczx-AI-Hub-claude
npx prisma generate && npm run build
PORT=3001 HTTPS_PORT=0 npx next start -H 0.0.0.0    # 换端口，避免和 dev 的 3000/3443 冲突
```

注意：另一个目录的 `.env` 如果指向同一个数据库文件，两边会同时写同一个库。只做验证时建议让它的 `DATABASE_URL` 指向一份测试库副本。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 整站白屏、无法登录，终端报 `Cannot find module './xxxx.js'`，静态资源 404 | dev 运行时在同一目录执行了 build，`.next/` 被覆盖 | 停掉所有 Next 进程 → `rm -rf .next` → 重新 `npm run dev`（或重新构建生产） |
| 启动报 `EADDRINUSE: address already in use :::3000` | 旧服务还没停 | `lsof -i :3000` 找到进程，`bash stop.sh` 或 `pkill -9 -f next-server` 后再启动 |
| 日志提示 `[HTTPS 入口] 端口 3443 已被占用，跳过` | 另一个 Next 进程占着 3443 | 停掉旧进程；或在 `.env` 设置 `HTTPS_PORT=其他端口`，不需要录音时设为 `0` |
| 生产模式下改了代码但页面没变化 | 生产模式不热更新 | 停服务 → 重新 `npx prisma generate && npm run build` → 启动 |
| 构建失败，报 TypeScript 类型错误 | 项目要求构建时类型 0 错误 | 运行 `npx tsc --noEmit` 定位并修复代码，**不要**把 `ignoreBuildErrors` 改回 `true` |
| 报 Prisma 相关错误，如字段不存在、`did you run prisma generate` | 漏了 `prisma generate`，或改了 schema 没同步数据库 | 备份数据库 → `npx prisma db push` → `npx prisma generate && npm run build` |
| 切换后看到的数据不对、像是空库或测试数据 | `.env` 的 `DATABASE_URL` 指向了别的库（当前本机就指向 `/tmp/wczx-test.db`） | `node scripts/db-locate.mjs` 查看真实路径，按需改回 `file:./dev.db` 后重启 |
| 开发模式首次打开页面很慢 | dev 模式按需编译 | 正常现象；需要测真实速度请切到生产模式 |
| 关掉终端后生产服务就停了 | 前台运行 | 用第 4 节的 `nohup ... &` 后台方式启动 |

## 9. 速查卡

```bash
# ── dev → 生产 ──
# 先在 dev 窗口 Ctrl + C，或：
bash stop.sh
npx prisma generate && npm run build
npx next start -H 0.0.0.0 -p 3000

# ── 生产 → dev ──
pkill -9 -f next-server
rm -rf .next
npm run dev
```
